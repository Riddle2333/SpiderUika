1最小窗口 简单

import tkinter as tk

root = tk.Tk()              # ① 创建主窗口
root.title("测试")          # ② 窗口标题
root.geometry("400x300")    # ③ 宽x高（小写 x）

tk.Label(root, text="Hello").pack()   # ④ 放一个文字控件

root.mainloop()             # ⑤ 进入事件循环（死循环）

三句话记住

tk.Tk()
整个程序只能有一个。它就是那个窗口
.pack()
「把控件塞进容器」，不调用它就看不见
mainloop()
阻塞在这里等用户操作。写在这之后的代码永远不会执行，直到窗口被关闭
坑 1：忘了 mainloop() → 窗口闪一下立刻消失。
坑 2：把初始化代码写在 mainloop() 之后 → 永远不执行。

3布局 pack 中等

pack() 是最简单的布局：把控件一个个「塞」进容器。

四个最常用的参数

side
"top"(默认) / "bottom" / "left" / "right" —— 往哪边塞
fill
"x" 横向撑满 / "y" 纵向撑满 / "both" 都撑满
expand
True 时，父容器多出来的空间分给它
padx / pady
外边距（像素）。padx=8 或 padx=(8,16)（左右不同）

从左到右排按钮

tk.Button(root, text="A").pack(side="left")
tk.Button(root, text="B").pack(side="left")
tk.Button(root, text="C").pack(side="left")
# → [A][B][C]  紧挨着

左右分列

tk.Button(root, text="左").pack(side="left")
tk.Button(root, text="右").pack(side="right")
# → [左]                    [右]  
# 注意：先 pack 的靠边，后 pack 的往中间挤

box3 里 pack 的顺序： ① btn_start side=left → [开始] ② btn_stop side=left → [开始][停止] ③ 打开文件夹 side=left → [开始][停止][打开输出文件夹] ④ progress side=right fill=x expand=True → 从右边开始，吃掉剩下的所有横向空间 ⑤ progress_label side=right → 贴在 progress 左边 最终: [开始][停止][打开输出文件夹] [0/85 (0%)][████░░░░░░]
为什么 progress 用 side="right" 而不是 "left"？
因为按钮都在左边。side="right" + expand=True 让它从右边开始往左撑满剩余空间， 自动避开左边的按钮——不用算宽度。

# 等价于 box1.pack(fill="x", padx=8, pady=4)
# ** 把字典拆成关键字参数

pack 和 grid 不要混用

同一个父容器里，要么全用 pack，要么全用 grid。混用会导致窗口卡死或不显示。
你的 ui.py 全程只用 pack，是对的。

5事件与回调 中等

两种绑定方式

# 方式 A：command=  —— 按钮/单选/多选专用，不传参数
tk.Button(root, text="点我", command=on_click)

# 方式 B：bind()  —— 任何控件、任何事件
widget.bind("<Button-1>", on_mouse)       # 鼠标左键
widget.bind("<Return>", on_enter)         # 回车
combo.bind("<<ComboboxSelected>>", on_pick)  # 下拉选中

回调函数的参数差异

def via_command():
    # command= 不传参数
    print("点了")

def via_bind(event):
    # bind() 会传一个 event 对象
    print("点了", event.widget)

▸ ui.py 第 56 行：下拉框选中时刷新

self.char_combo.bind("<<ComboboxSelected>>",
                     lambda e: self._on_kind_changed())

这里用 lambda 是因为：bind 会传 event， 而 _on_kind_changed(self) 不需要它，所以用 lambda 吃掉。

lambda 传参陷阱

# ❌ 错误：四个按钮都打印 3
for i in range(4):
    tk.Button(root, text=f"按钮{i}",
              command=lambda: print(i)).pack()

# ✅ 正确：用默认参数把当前值"冻住"
for i in range(4):
    tk.Button(root, text=f"按钮{i}",
              command=lambda n=i: print(n)).pack()
这是因为 lambda 捕获的是变量而不是值。 循环结束后 i 永远是 3。加 n=i 就变成了默认参数，创建时就求值固定住了。

6线程 —— 真正难的地方 难点

先看错误示范

import time

def slow_click():
    for i in range(10):
        log.insert("end", f"第 {i} 步\n")
        root.update()          # 临时刷新
        time.sleep(1)           # ← 元凶

tk.Button(root, text="开始", command=slow_click).pack()

点下去之后：窗口完全冻住，拖不动、点不了、标题栏显示「未响应」。

为什么

tkinter 是单线程的： 主线程 ├── 跑 mainloop() │ └── 每 1ms 检查：有没有鼠标点击？有没有键盘输入？有没有要重绘的？ └── 调用你的 slow_click() └── 这一跑就是 10 秒，mainloop 完全停摆 └── 期间所有事件被堵在队列里 → 界面假死

正确做法：甩到子线程

import threading

def on_start():
    threading.Thread(target=worker, daemon=True).start()

def worker():
    # 这里很慢也没关系，不阻塞主线程
    for i in range(10):
        time.sleep(1)
        # ❌ 但这里不能直接碰控件！见下一章

tk.Button(root, text="开始", command=on_start).pack()

daemon=True 是什么

daemon=True
主线程退出时，子线程被强制杀掉。不加的话，关窗口后程序可能还在后台跑
什么时候需要线程
任何超过 ~0.1 秒的操作：网络请求、文件读写、音频转换、爬虫。
你这个项目「下载 85 个故事」要 30 分钟，**必须**线程。

7队列 —— 线程安全通信 难点

为什么子线程不能直接改控件

def worker():
    log.insert("end", "完成\n")   # ← 危险！

tkinter 底层是 Tcl 解释器，**不是线程安全的**。从别的线程操作控件会出现：

Tcl_AsyncDelete: async handler deleted by the wrong thread 或者 RuntimeError: main thread is not in main loop 或者 程序毫无征兆地崩溃

而且这些错误**时有时无**，非常难复现。

规则

只有主线程能碰控件。子线程要做的事只有一件：把消息放进队列。

Queue = 传送带

子线程 主线程 ───── ───── log("下载OK") ──put──▶ ┌──────────────┐ ──get──▶ 更新界面 log("下载OK") ──put──▶ │ queue.Queue │ 进度(3/10) ──put──▶ └──────────────┘ （内部自动加锁，多线程安全）

完整骨架

import queue
import threading

msg_queue = queue.Queue()

# ---------- 子线程：只往队列塞 ----------
def worker():
    for i in range(5):
        time.sleep(1)
        msg_queue.put(("log", f"第 {i} 步"))
        msg_queue.put(("progress", i + 1, 5))
    msg_queue.put(("done", None))

# ---------- 主线程：定时读队列、更新控件 ----------
def poll():
    try:
        while True:
            msg = msg_queue.get_nowait()      # 立即取，取不到抛 Empty
            kind = msg[0]
            if kind == "log":
                log.insert("end", msg[1] + "\n")
            elif kind == "progress":
                bar["value"] = msg[1] / msg[2] * 100
            elif kind == "done":
                return                        # 不再自我调度
    except queue.Empty:
        pass
    root.after(80, poll)                    # 80ms 后再来一次

消息协议：为什么用元组

("log", "下载完成")        # 第 1 个元素是类型
("progress", 3, 10)       # 后面跟数据
("done", None)

用一个队列传多种消息时，必须带类型标签，否则主线程不知道该干什么。

▸ ui.py 第 300~330 行

展开看完整的 _push_log / _push_progress / _poll_queue 
def _push_log(self, text):
    self.msg_queue.put(("log", str(text)))

def _push_progress(self, done, total):
    self.msg_queue.put(("progress", done, total))

def _poll_queue(self):
    try:
        while True:
            msg = self.msg_queue.get_nowait()
            kind = msg[0]
            if kind == "log":
                self._append_log(msg[1])
            elif kind == "progress":
                self._update_progress(msg[1], msg[2])
            elif kind == "done":
                self._on_finished()
    except queue.Empty:
        pass
    self.root.after(80, self._poll_queue)
为什么用 while True 一次性抽干？
因为每秒可能产生几十条日志。一次全取完比每次只取一条效率高。 get_nowait() 在队列空时抛 Empty，正好结束循环。

8after 定时器 中等

它不是 sleep

写法行为
time.sleep(0.1)主线程真的卡住 0.1 秒，界面无响应
root.after(100, func)告诉 mainloop「100ms 后帮我调 func」，期间界面照常响应

自我调度 = 轮询循环

def poll():
    check_queue()              # 干活
    root.after(80, poll)      # 安排下一次

root.after(80, poll)          # 启动第一次
root.mainloop()
mainloop 内部大致是这样： while 窗口还在: 处理鼠标/键盘事件 重绘需要刷新的控件 检查有没有到期的 after() → 有就调用它 循环

三种启动方式

root.after(1000, once)          # 1 秒后执行一次（不重复）

def loop():
    do_work()
    root.after(100, loop)      # 自己安排自己 → 无限循环
loop()

job = root.after(100, loop)
root.after_cancel(job)             # 取消

轮询间隔怎么选

50~100 ms
日志/进度，人眼几乎无延迟感，CPU 占用很低
200~500 ms
不需要实时的状态
< 30 ms
❌ 没必要，白白增加 CPU

你的 ui.py 用 80ms，是个合适的值。

9停止机制 中等

不能用 sys.exit 或 kill 线程

# ❌ 会杀掉整个程序，.part 临时文件残留
def stop():
    sys.exit()

# ❌ Python 没有安全的杀线程方法（thread.kill 不存在）
thread.kill()

正确：协作式停止（Event）

stop_event = threading.Event()      # 初始化：未触发

# ---- 主线程（按钮回调）----
def on_stop():
    stop_event.set()                # 打个标记

# ---- 子线程（循环里检查）----
def worker():
    for i in items:
        if stop_event.is_set():     # ← 主动检查
            print("已停止")
            return
        干活(i)
「协作式」的含义：没有人能强行打断线程，只能靠线程自己检查并退出。 所以检查点要放在循环里，且要足够密集。

import queue, threading
import tkinter as tk
from tkinter import ttk, scrolledtext

from tools import make_session
from story_scraper import story_id_scraper

root = tk.Tk()
q = queue.Queue()

entry = ttk.Entry(root, width=20)
entry.pack()
log = scrolledtext.ScrolledText(root, height=12)
log.pack(fill="both", expand=True)
log.configure(state="disabled")

def put(t):
    q.put(("log", t))

def worker():
    try:
        cid = entry.get().strip()
        put(f"查询角色 {cid} ...")
        ids = story_id_scraper(make_session(), cid, True)
        put(f"共 {len(ids)} 个故事")
        put("前 5: " + str(ids[:5]))
    except Exception as e:
        put(f"出错: {e}")
    finally:
        q.put(("done", None))

def on_click():
    threading.Thread(target=worker, daemon=True).start()
    root.after(80, poll)

def poll():
    try:
        while True:
            msg = q.get_nowait()
            if msg[0] == "log":
                log.configure(state="normal")
                log.insert("end", msg[1] + "\n")
                log.see("end")
                log.configure(state="disabled")
            elif msg[0] == "done":
                return
    except queue.Empty:
        pass
    root.after(80, poll)

ttk.Button(root, text="查询", command=on_click).pack()
root.mainloop()
